## [0.4.0](https://github.com/OpenRAL/openral/compare/v0.3.1...v0.4.0) (2026-11-13)


### ⚠ BREAKING CHANGES

* **dashboard:** the robot console can no longer be built from this repository. The pinned bundle is still downloaded and served as before, and it stays Apache-2.0. OPENRAL_DASHBOARD_UI_DIR (your own UI build, or an empty directory for the fallback page) serves a different UI, and the robot API is the public contract for third-party UIs.
* **security:** a real cell spanning hosts with only OPENRAL_ALLOW_NETWORK_ROS=1 no longer launches; run `openral security init` and export the ROS_SECURITY_* variables.
* **hal:** AlohaHAL drops the left/right_arm_controller and left/right_gripper_controller kwargs (now arm_group, gripper_name, gripper_cmd_range, arm_namespaces); connect() now refuses without an injected publish_fn and state_fn.
* **dashboard:** the vanilla UI, POST /api/estop, /api/estop_reset, /api/prompt, /api/skill/execute, /api/param/set and the MJPEG camera stream are removed; use POST /api/actions/{id}. Free-form parameter writes are gone, and a non-loopback client may no longer post OTLP or anything but E-STOP.
* **rskill:** an rSkill manifest declaring role "s0" is refused (S0 is never an rSkill). Under schema_version "0.2" (the new default) a role that disagrees with the kind is refused; "0.1" files migrate it with a UserWarning. rSkill.from_yaml / from_pretrained / load_rskill_manifest raise ROSConfigError, not pydantic.ValidationError (no longer a ValueError), for an invalid manifest. The ExecuteRskill runner refuses non-dispatchable kinds and actuating skills tagged "any", and gates sensors and capability flags before it loads anything.
* **safety:** kExemptionProviderApiVersion is 5; a v4 provider is refused at load ("refused: api_version 4 != 5"). BrakeConfig/brake_config are replaced by WorkspaceContactConfig/workspace_contact_config.
* **world-state:** scenes running object_tracking=tracking need a search_box enclosing the target for a grasp region and a declared place zone for a place allowance; carried objects are no longer cleared from the map outside `on`.
* **world-state:** tracked boxes and payload hulls no longer contain hidden parts past the measured footprint. Safety-WG review and a hazard-log row owed (A4 no longer holds).
* **sim:** an nf4/int8 LingBot or BEHAVIOR GR00T sidecar started by hand needs --pro-quant-module as well as --quantization-config.
* **deps:** bitsandbytes leaves open's dependency groups (ADR-0123 step 3) ([#444](https://github.com/OpenRAL/openral/issues/444))
* **sim:** openral_sim._quantization no longer exports quantize_nf4_in_place, quantize_int8_in_place, install_prequantized_linears, overlay_prequantized_state, detect_prequantized_nf4, load_prequantized_state_for_rskill or DEFAULT_MIN_PARAMS_TO_QUANTIZE.
* **rskill:** the 20 int4/int8 rSkills (OpenVLA-OFT, MolmoAct2, RLDX, XR-1, GR00T N1.7, LingBot, InternVLA-N1, pi05-libero-int8, Qwen3.5 4B, LocateAnything, TopReward, Robometer) no longer load on an open-only install. OPENRAL_QUANTIZATION_DTYPE=bf16 runs a model at bf16 where it fits.
* **world-state:** the parameters above are gone from openral_safety_kernel.
* **safety:** the parameters above are gone from openral_safety_kernel.
* **robots:** the OpenArm `top` camera's slot is `top` (was `base`). An OpenArm rSkill must require `observation.images.top`, and a deploy scene must not restate the camera's `vla_feature_key`.
* `ros2 run openral_hal_<robot>` entry points are gone; launch `openral_hal_node` with the robot manifest instead. `openral_core.RoboCasaBackendOptions` moved to `openral_sim.backends.robocasa` and its JSON schema is no longer exported. tabletop_push / so101_box `backend_options` are validated; `joint_units` must be exactly `radians` or `degrees`. `openral_rskill.quantization`, `openral_rskill.engine_cache` and `VLASpec.runtime` are removed. the `image_modality_keys`, `image_key` and lingbot/rldx `camera_keys` policy extras are ignored; declare camera aliases in the manifest. the pusht_2d sensor slot is `camera1`. `HalEntrypoints.real_bringup` is declared-only; the deploy launch no longer includes it.
* `openral_runner.sensor_name_to_slot` moved to `openral_core`; `image_preprocessing.aliases` keys must be VLA slots (`camera1`, ...) and unknown keys raise; an unsupported manifest `quantization.dtype` now raises instead of loading another dtype; `OPENRAL_LINGBOT_VLA{,2}_QUANTIZATION` and `vla.extra.quantization` are removed; `n_action_steps > chunk_size` and `n_action_steps < 1` are rejected; `deploy sim` rejects a `robot_id` outside the scene's robot set.
* the `openral-wam` distribution and the `openral_wam` package (`WorldModel`, `Rollout`, `NullWorldModel`) are no longer published from this repo.
* **ci:** test-selective's `select-and-test` job no longer runs the opt-in dependency lanes; they moved to a separate `lane` matrix gated behind the `heavy-lanes` GitHub Environment, which is a new required status check.
* **scenes:** drop the OpenArm restock deploy scene ([#284](https://github.com/OpenRAL/openral/issues/284))
* **sim:** `OPENRAL_GR00T_QUANTIZATION`, `OPENRAL_GR00T_QUANTIZE_SCOPE` and `OPENRAL_RLDX_QUANTIZATION` are replaced by `OPENRAL_QUANTIZATION_DTYPE`; `policy_extras.quantization` / `.quantize_scope` / `.nf4_min_params` move to `quantization.dtype` / `quantization.extra`. No back-compat aliases, matching how `--vla` was retired. The three in-tree manifests are migrated in this commit.
* **safety:** the kernel discloses which occupancy grid a voxel stop checked ([#281](https://github.com/OpenRAL/openral/issues/281))
* **rskill:** `--rskill act-so101-pen` and `--rskill gr00t-n17-so101-fruit` no longer resolve in-tree. Their upstream checkpoints (`gabrycina/so101-passing-pen-policy`, `aaronsu11/GR00T-N1.7-3B-SO101-FruitPicking`) are unaffected and still installable by Hub id.
* **rskill:** `--rskill smolvla-so101-pen`, `--rskill smolvla-so101-pick-place-pen` and `--rskill rskills/rskill-pi05-openarm-restock_shelf-bf16` no longer resolve in-tree. Install the equivalent from the Hub, or use `rskill-smolvla-so101-eraser_place-bf16` for SO-101 SmolVLA work.
* **launch:** take the real-hardware world-voxel grid to 20 mm
* **launch:** ship the sim world-voxel grid at 15 mm
* **scenes:** this scene's head camera publishes on `/openral/cameras/top/image`, not `/openral/cameras/context/image`. A saved Foxglove layout pointed at the old topic needs re-importing; the layout the deploy generates is already correct.
* **robots,launch:** `robots/openarm/openarm.urdf` now spells joints and links as upstream does (`openarm_left_joint1`, `openarm_left_base_link`) instead of the stripped `left_joint1` / `left_base_link`. Anything reading that file by link or joint name must use the new spelling. The manifest's logical joint names are unchanged.
* **cli:** `OPENRAL_ALLOW_SHARED_GRAPH` is removed. Its narrowed replacement `OPENRAL_ALLOW_UNVERIFIED_GRAPH` waives only the unreadable-graph refusal; nothing waives the occupied-graph one. Setting the old name now does nothing.
* **safety:** check panda_link5 / panda_link7 at hull fidelity instead of exempting it ([#202](https://github.com/OpenRAL/openral/issues/202))
* **nav:** the `payload_footprint` launch arg is renamed `payload_scan_filter` and no longer starts a footprint publisher; `openral_nav2_bringup.payload_footprint_node` is removed. Nav2's footprint is now the manifest's bare chassis, substituted statically at launch by `RobotDescription.nav2_param_overrides()`.
* **safety:** `CollisionHit` gains `advisory`, and a payload contact inside a live place declaration within `place_advisory_depth` of the allowance no longer latches or asserts E-stop. Set `place_advisory_max_consecutive: 0` to restore the previous behaviour exactly.
* **collision:** publish the world grid on the map's own lattice, not the base frame's
* **sim:** the two `test_depth_camera_synth.py` tests asserting that a visual-only countertop must be the reported surface are inverted deliberately. Their scene is kept because it is the adversarial one — the slab is built to fall outside its body's collision BVH — but its physical surface is the carcass at 0.890; 0.920 is paint, and an arm passes through it.
* **msgs:** return candidate masks from SegmentInView, select on geometry in the HAL

### ⚠ BREAKING CHANGES

* **reasoner:** the deprecated `OPENRAL_REASONER_LLM_*` provider-first env contract is removed (ADR-0088; deprecated in 0.2.0 as a one-release shim). An environment that sets only those variables now fails with "`OPENRAL_REASONER_MODEL` is unset" instead of silently selecting a model — deliberate, so a reasoner driving real hardware refuses to start on stale configuration rather than picking something unintended.

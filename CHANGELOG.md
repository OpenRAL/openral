## [0.4.0](https://github.com/OpenRAL/openral/compare/v0.3.1...v0.4.0) (2026-10-31)


### ⚠ BREAKING CHANGES

* **sim:** an nf4/int8 LingBot or BEHAVIOR GR00T sidecar started by hand needs --pro-quant-module as well as --quantization-config.
* **deps:** bitsandbytes leaves open's dependency groups (ADR-0123 step 3) ([#444](https://github.com/OpenRAL/openral/issues/444))
* **sim:** openral_sim._quantization no longer exports quantize_nf4_in_place, quantize_int8_in_place, install_prequantized_linears, overlay_prequantized_state, detect_prequantized_nf4, load_prequantized_state_for_rskill or DEFAULT_MIN_PARAMS_TO_QUANTIZE.
* **rskill:** the 20 int4/int8 rSkills (OpenVLA-OFT, MolmoAct2, RLDX, XR-1, GR00T N1.7, LingBot, InternVLA-N1, pi05-libero-int8, Qwen3.5 4B, LocateAnything, TopReward, Robometer) no longer load on an open-only install. OPENRAL_QUANTIZATION_DTYPE=bf16 runs a model at bf16 where it fits.
* **world-state:** the parameters above are gone from openral_safety_kernel.
* **safety:** the parameters above are gone from openral_safety_kernel.
* **robots:** the OpenArm `top` camera's slot is `top` (was `base`). An OpenArm rSkill must require `observation.images.top`, and a deploy scene must not restate the camera's `vla_feature_key`.
* `ros2 run openral_hal_<robot>` entry points are gone; launch `openral_hal_node` with the robot manifest instead. `openral_core.RoboCasaBackendOptions` moved to `openral_sim.backends.robocasa` and its JSON schema is no longer exported. tabletop_push / so101_box `backend_options` are validated; `joint_units` must be exactly `radians` or `degrees`. `openral_rskill.quantization`, `openral_rskill.engine_cache` and `VLASpec.runtime` are removed. the `image_modality_keys`, `image_key` and lingbot/rldx `camera_keys` policy extras are ignored; declare camera aliases in the manifest. the pusht_2d sensor slot is `camera1`. `HalEntrypoints.real_bringup` is declared-only; the deploy launch no longer includes it.
* `openral_runner.sensor_name_to_slot` moved to `openral_core`; `image_preprocessing.aliases` keys must be VLA slots (`camera1`, ...) and unknown keys raise; an unsupported manifest `quantization.dtype` now raises instead of loading another dtype; `OPENRAL_LINGBOT_VLA{,2}_QUANTIZATION` and `vla.extra.quantization` are removed; `n_action_steps > chunk_size` and `n_action_steps < 1` are rejected; `deploy sim` rejects a `robot_id` outside the scene's robot set.
* the `openral-wam` distribution and the `openral_wam` package (`WorldModel`, `Rollout`, `NullWorldModel`) are no longer published from this repo.
* **ci:** test-selective's `select-and-test` job no longer runs the opt-in dependency lanes; they moved to a separate `lane` matrix gated behind the `heavy-lanes` GitHub Environment, which is a new required status check.
* **scenes:** drop the OpenArm restock deploy scene ([#284](https://github.com/OpenRAL/openral/issues/284))
* **sim:** `OPENRAL_GR00T_QUANTIZATION`, `OPENRAL_GR00T_QUANTIZE_SCOPE` and `OPENRAL_RLDX_QUANTIZATION` are replaced by `OPENRAL_QUANTIZATION_DTYPE`; `policy_extras.quantization` / `.quantize_scope` / `.nf4_min_params` move to `quantization.dtype` / `quantization.extra`. No back-compat aliases, matching how `--vla` was retired. The three in-tree manifests are migrated in this commit.
* **safety:** the kernel discloses which occupancy grid a voxel stop checked ([#281](https://github.com/OpenRAL/openral/issues/281))
* **rskill:** `--rskill act-so101-pen` and `--rskill gr00t-n17-so101-fruit` no longer resolve in-tree. Their upstream checkpoints (`gabrycina/so101-passing-pen-policy`, `aaronsu11/GR00T-N1.7-3B-SO101-FruitPicking`) are unaffected and still installable by Hub id.
* **rskill:** `--rskill smolvla-so101-pen`, `--rskill smolvla-so101-pick-place-pen` and `--rskill rskills/rskill-pi05-openarm-restock_shelf-bf16` no longer resolve in-tree. Install the equivalent from the Hub, or use `rskill-smolvla-so101-eraser_place-bf16` for SO-101 SmolVLA work.
* **launch:** take the real-hardware world-voxel grid to 20 mm
* **launch:** ship the sim world-voxel grid at 15 mm
* **scenes:** this scene's head camera publishes on `/openral/cameras/top/image`, not `/openral/cameras/context/image`. A saved Foxglove layout pointed at the old topic needs re-importing; the layout the deploy generates is already correct.

### ⚠ BREAKING CHANGES

* **reasoner:** the deprecated `OPENRAL_REASONER_LLM_*` provider-first env contract is removed (ADR-0088; deprecated in 0.2.0 as a one-release shim). An environment that sets only those variables now fails with "`OPENRAL_REASONER_MODEL` is unset" instead of silently selecting a model — deliberate, so a reasoner driving real hardware refuses to start on stale configuration rather than picking something unintended. Every provider the old contract reached is expressible model-first via `OPENRAL_REASONER_ENDPOINT`, which accepts the named endpoints `anthropic` / `openrouter` / `gemini` / `xai` / `deepseek` / `huggingface` / `ollama` / `vllm`. Migration table: [`packages/openral_reasoner_ros/README.md`](https://github.com/OpenRAL/openral/blob/master/packages/openral_reasoner_ros/README.md).

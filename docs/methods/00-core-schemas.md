# Layer 0 — Core Schemas & Exceptions

> Part of the OpenRAL [public-symbol inventory](../METHODS.md). Hand-curated; `(LNN)` markers are refreshed by `tools/refresh_methods_linenos.py`.

Authoritative Pydantic v2 contracts. Anything imported from `openral_core.__init__` is API. On-disk schemas (`RobotDescription`, `RSkillManifest`, `SceneGraph`, …) are versioned via `schema_version` and evolve in place unless a change breaks compatibility.

### `python/core/src/openral_core/depth_extrinsic.py`
_The depth-camera extrinsic a real world-voxel deploy runs on. ### `python/core/src/openral_core/time_base.py`
_The deploy-sim time base — one `env.step` / `send_action` is one control period (issues #355, #358). Every sim backend derives its physics steps per tick here and every sim HAL holds the backend to the robot's rate here._

- `TIME_BASE_TOL: float` — `0.01`: tolerance on `sim_dt_per_tick_s * control_freq_hz == 1`. (L19)
- `physics_steps_per_tick(control_freq_hz, physics_dt_s) -> tuple[int, float]` — `(steps, dt_s)` with `steps * dt_s == 1 / control_freq_hz` exactly; (L22) keeps the engine dt when it already divides the period, otherwise **shrinks** it (never grows) to the largest value at or below `physics_dt_s` that does (MuJoCo's 0.002 s at 30 Hz: 16.67 steps → 17 at 1/510 s). `ROSConfigError` on a non-finite / non-positive rate or dt. Used by `MujocoArmHAL._resolve_time_base` and `openral_sim.rollout.pin_robosuite_time_base`.
- `check_time_base(sim_dt_per_tick_s, control_freq_hz, *, backend, robot) -> None` — Refuses (`ROSConfigError`) a tick that is not one control period within `TIME_BASE_TOL` (NaN refused too), or a manifest with no rate (`control_freq_hz=None`). (L60) The one guard behind `SimAttachedHAL._check_time_base` and the twin.
- `scene_control_rate_hz(backend_options, robot_hz) -> float | None` (L100) — The rate a sim scene steps: a finite positive `backend_options.control_freq_hz` (a bool, string, NaN, inf or non-positive value is a `ROSConfigError`), else `robot_hz`. Shared by `openral_sim.cli._scene_control_rate_hz` (video / dataset fps) and `sim_scene_description` (deploy sim).

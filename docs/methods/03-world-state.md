### `python/state_adapter/src/openral_state_adapter/`
_Layout adapter registry. Assembles per-checkpoint state vectors from manifest-declared `StateContractBindings` + live `/tf` + live `/joint_states`. Pure-Python, rclpy-free; the skill_runner wraps `tf2_ros.Buffer.lookup_transform` into the `TfLookup` Protocol at call time._

- `@dataclass TransformView` — rclpy-free view of a `geometry_msgs/TransformStamped`. Fields: `position: tuple[float, float, float]`, `quaternion_xyzw: tuple[float, float, float, float]`.
- `Protocol TfLookup` — `__call__(target_frame: str, source_frame: str) -> TransformView`. Implementations MUST raise on missing transforms — assembler never silently substitutes identity.
- `Protocol Assembler` — `__call__(bindings: StateContractBindings, joint_positions: dict[str, float], tf_lookup: TfLookup) -> NDArray[float32]`. Pure-function signature every layout file implements.
- `register(layout: StateLayout, assembler: Assembler) -> None` — Bind `assembler` to `layout` in the package-global registry. Layout files call this at module load.
- `registered_layouts() -> frozenset[StateLayout]` — Snapshot of currently-registered layouts. Reasoner palette filter consults this to admit wrapped-task-space rSkills.
- `assemble_state(layout, bindings, joint_positions, tf_lookup) -> NDArray[float32]` — Look up the assembler for `layout` and run it. Raises `ROSConfigError` when no assembler is registered.
- `assemble_human300_16d(bindings, joint_positions, tf_lookup) -> NDArray[float32]` — RoboCasa365 / pi05_pretrain_human300 layout: `[base_to_eef.pos(3), base_to_eef.quat(4), world_to_base.pos(3), world_to_base.quat(4), gripper_qpos(2)] = 16`. Registered as `"human300_16d"` at import.
- `assemble_libero_eef8d(bindings, joint_positions, tf_lookup) -> NDArray[float32]` — LIBERO task-space layout: `[eef_pos(3), eef_axisangle(3), gripper_qpos(2)] = 8`, world-frame EE pose via `tf_lookup(bindings.world_frame, bindings.eef_frame)` + axis-angle (byte-matching the benchmark `openral_sim.backends.libero._quat_to_axisangle`, `[x,y,z,w]`→`axis·2·acos(w)`) + gripper (1 joint mirrored to `[v,-v]` or 2 per-finger). Registered as `"libero_eef8d"` at import. Lets `openral deploy sim` feed the lerobot/smolvla_libero (and pi05-/xvla-libero) checkpoints the same task-space proprio they get in the benchmark (else the runner falls back to raw joint-space state and the policy fails). `world_frame` defaults to `"map"` (SLAM root) on the binding — LIBERO manifests MUST set it to the HAL sim root.

### `python/world_state/src/openral_world_state/object_lift.py`
_2D→3D object-center lift helpers — pure, ROS-free, unit-testable._

- `class ObjectsLiftError(ValueError)` — Raised by geometry helpers on degenerate inputs (zero-norm quaternion; occupancy buffer size mismatch). (L38)
- `homogeneous_from_quat_xyz(translation, quat_xyzw) -> NDArray[np.float64]` — Build a 4×4 homogeneous transform from a translation + xyzw quaternion (normalised). Raises `ObjectsLiftError` if the quaternion norm is effectively zero. **Thin wrapper since the SAM 2.1 attachment work**: the math lives in `openral_core.geometry.homogeneous_from_quat_xyz` (the layer-0 HAL needs the same TF→matrix step and must not depend on layer 2), and this function re-raises the core `ROSConfigError` as the world-state-local `ObjectsLiftError` so every caller here is unaffected. (L42)
- `decode_occupied_centers(*, origin, resolution, size_xyz, occupancy) -> NDArray[np.float64]` — Occupied voxel centres `(N, 3)` in the grid frame; row-major x-fastest. Center of cell `(ix, iy, iz)` = `origin + (index + 0.5) * resolution`. Returns `(0, 3)` when none are occupied. Raises `ObjectsLiftError` if `len(occupancy) != size_x * size_y * size_z`. (L72)
- `depth_cloud_to_centers_base(points_cloud, t_base_from_cloud, *, max_points=0) -> NDArray[np.float64]` — #11 octomap-free fallback depth source for `VoxelFrustumLifter`: drops non-finite returns, uniformly subsamples to `max_points` (0 = no cap), and maps the `(N, 3)` cloud from its optical frame into the base frame. Output is interchangeable with `decode_occupied_centers` as the lifter's `occupied_centers_base`. Returns `(0, 3)` when the cloud has no finite points. (L118)
- `aabb_iou_3d(a, b) -> float` — 3D axis-aligned bbox IoU in `[0, 1]`. Boxes are `(xmin, ymin, zmin, xmax, ymax, zmax)`. Returns 0.0 for disjoint or degenerate boxes. This is the single IoU helper in the repo — reuse it; do not add another. (L154)
- `class VoxelFrustumLifter(*, k_nearest=25, min_voxels=3)` — Lift 2D detections to 3D object centres via voxel-frustum K-nearest. Frustum-projects `/openral/world_voxels` occupied centres into the RGB camera image plane (using `SensorSpec.intrinsics` + TF2 transforms), selects the K voxels nearest each box centre, and returns one `DetectedObject` per detection with `pose.frame_id = "map"`. Skips a detection when fewer than `min_voxels` voxels survive the frustum filter. (L180)
  - `lift(*, detections, occupied_centers_base, intrinsics, frame_size, t_cam_from_base, t_map_from_base, map_frame="map") -> list[DetectedObject]` — Core lift call (vectorised over voxels; per-detection masking after). Returns `[]` when `occupied_centers_base` is empty (best-effort). `track_id` is set from the 2D detection's `det_id` (`det.det_id` if `>= 0`, else `None`) — propagating detection-time identity into 3D so a physical object keeps one id across the 2D `in_view` line and 3D `scene_objects`; `ObjectMemory` adopts it for new tracks. (L199)
- `build_in_fov_predicate(*, intrinsics, t_cam_from_map) -> Callable[[DetectedObject], bool]` — Build a predicate that returns `True` iff the object's `map`-frame centre is in front of the camera and projects within the image bounds (`(0, 0)` to `(intrinsics.width, intrinsics.height)`); behind-camera or out-of-bounds → `False`. Used by `ObjectMemory.tick` for FOV-guarded eviction. (L294)

### `python/world_state/src/openral_world_state/object_memory.py`
_IoU-gated spatial object memory — pure, ROS-free, unit-testable._

- `class ObjectMemory(*, iou_threshold=0.3, max_misses=1)` — IoU-gated spatial memory with freeze-on-match, in-FOV-guarded eviction, and out-of-FOV retention. Maintains a monotonic `track_id` counter. (L30)
  - `tick(candidates: list[DetectedObject], *, stamp_ns: int, in_fov: Callable[[DetectedObject], bool]) -> list[DetectedObject]` — Run one association+eviction step. Greedy highest-confidence-first matching: same-label + `aabb_iou_3d ≥ iou_threshold` → freeze (leave pose/bbox unchanged, bump confidence, reset miss count); no match → new track (adopts the candidate's incoming `track_id` — the detector's `det_id` — when `>= 0`, else mints a fresh monotonic id; matched tracks keep their stored id since 3D association is more stable than 2D re-id). Unmatched existing tracks: `in_fov` true → `miss_count += 1`; evict when `miss_count >= max_misses`; `in_fov` false → retain unchanged. Returns surviving tracks as `list[DetectedObject]`. (L64)

### `packages/openral_octomap_bridge/include/openral_octomap_bridge/payload_clearing.hpp`
_C++ (Layer 2). The attached payload's own occupancy leaves the published `OccupancyVoxels` grid here — partitioned against the safety kernel's support-contact witness (ADR-0092 D6). Header-documented; gtested in `test/test_payload_clearing.cpp` against a real `octomap::OcTree`._

- `struct PayloadPrimitive` — One attached-payload collision primitive placed in the grid frame (`shape_type` matching `AttachedCollisionPrimitive::SHAPE_*`, `pose`, `radius`, `half_length`, `half_extents`). Same conventions as the kernel's `AttachedPrimitive`: a capsule's segment on local +Z, a box's half-extents on its own axes.
- `struct SupportPatch` — One attested support contact placed in the grid frame: `point`, unit outward `normal` (from the supporting solid **toward** the payload), `patch_radius`, `max_penetration`. The wire form is `openral_msgs/SupportContactWitness`, stated in the attached object's frame; this is it lifted through the payload's live pose.
- `place_attached_object(object, grid_from_link, out, out_patches) -> bool` — Place one wire `AttachedCollisionObject`'s primitives (`grid_from_link · pose_in_link · pose_in_object`, the kernel's own composition) and, when `support_contact_valid`, its one support patch (`grid_from_link · pose_in_link`). Fail-closed on the kernel's `ingest_attached_objects` rules — no primitives, unknown shape tag, short/non-finite/negative dimensions, degenerate quaternion, or a malformed attestation (non-finite point, degenerate normal, non-positive patch radius, negative penetration) — returning `false` and appending **nothing** to either output, so the caller clears nothing at all.
- `support_patch_withholds(patch, center, resolution) -> bool` — Does an attested patch claim this cell, and therefore forbid clearing it? The kernel's `support_contact_exempts` with `slack = 0`: inside the patch laterally (padded by the cell circumradius) and no higher above the attested plane than `half_resolution·(|n.x|+|n.y|+|n.z|) + max_penetration + resolution` — the support **half-space slab**, never the whole patch cylinder. The third term is the kernel's one voxel of co-planar headroom (hazard log Entry 012, "Calibration 2026-08-15"), mirrored here **in lockstep by obligation of that entry**: the containment below is a property of the two sides being the same inequality, so a height term in one and not the other breaks it by construction. Dropping the slack keeps the withheld set a **subset** of the kernel-exempt set for the object that attested it, so a withheld cell can never be the one that stops the robot against that object; the two scope conditions that qualify it (the kernel exempts per-object while the bridge withholds per-message, and the kernel's lifecycle node caps the attestation it accepts) are in `packages/openral_octomap_bridge/README.md`. Deliberate mirror of the kernel predicate — see [14-duplication-watch.md](14-duplication-watch.md) item 8.
- `clear_attached_payload_cells(grid, primitives, patches, padding_m) -> size_t` — Zero every occupied cell whose centre lies within `resolution·√3/2 + padding_m` of a payload primitive's surface **except** those a patch withholds; returns the count cleared. Withholding can only skip a clear, so the result is always a subset of the un-partitioned clearing: the partition puts occupancy back into the map and never takes any away. Never marks (only ever writes 0); a grid whose `occupancy` length disagrees with its dimensions, or with a non-positive resolution, is left untouched.
- `struct AttachedObjectRevision` — One payload's attachment-record identity: the wire `object_id` plus `WorldStateStamped.attachment_revision` (the producer's own counter, bumped once per atomic `AttachmentState` change, never per frame).
- `struct AttachSweepObservation` — That identity plus the payload's `payload_position` on one grid, stated in the **OctoMap's** frame (the residue the window chases is world-fixed, so a payload motionless in `base_link` on a driving base has still left it behind).
- `class AttachSweepLedger` — The bridge's only memory: the open attach-transition window per live object (identity, the position it is anchored at, whether it has shut). Not a latch on cells — nothing about which cells were cleared is remembered, and no cell is held out of a later grid.
  - `sweep(present, window_m) -> vector<uint8_t>` — Which of `present` are still inside their window, in order — **and** record this grid; answering and recording in one call is what stops the window's state and the reach it licenses from disagreeing. A key seen for the first time anchors where it is now, so its window is open (the attach transition itself); a window closes, and **latches** closed, once the payload has translated more than `window_m` from its anchor. An object absent from `present` is forgotten, so detach and the next grasp restart the window. Not calling it — a frame that clears nothing — leaves every window untouched, so the padded sweep stays owed. Position-based rather than one-shot because the grid is re-rasterized from the octree every tick: the 2026-08-14 round-5 E-stop fired ~28 published grids after the attach, with the payload unmoved.
  - `size() -> size_t` — How many windows the last swept grid carried.
- `attach_transition_padding(steady_padding_m, attach_sweep_padding_m) -> double` — The clearing padding one object gets on ONE grid: the steady value plus the attach-sweep value while its window is open, so the widened sweep is never *tighter* than an ordinary frame. Non-finite or negative inputs contribute 0 — a parameter cannot narrow the clearing below what the payload's volume explains. The extra reach exists for the stale pre-attach silhouette a fitted primitive leaves just outside one circumradius (the round-5 `voxel_91633`, 22.13 mm out at 25 mm cells); see `packages/openral_octomap_bridge/README.md`.

### `packages/openral_octomap_bridge/include/openral_octomap_bridge/octree_to_grid.hpp`

- `struct GridSpec` — Output lattice: `resolution`, `sx`/`sy`/`sz`, `box_min[3]` (the local volume's min corner in the base frame).
- `rasterize_octree_to_grid(tree, base_to_octomap, spec, base_frame) -> openral_msgs::msg::OccupancyVoxels` — Crop + rasterize a bounded local volume of a real `octomap::OcTree` into the kernel-facing dense grid: each base-frame cell centre is mapped into the octree frame by `base_to_octomap` (`lookupTransform(octomap_frame, base_frame)`) and queried. `header.frame_id = base_frame`, with `origin` in that same frame (the ADR-0095 frame contract).

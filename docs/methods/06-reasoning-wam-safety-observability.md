# Layer 4–6 — Reasoning, Safety, Observability (plus WAM)

> Part of the OpenRAL [public-symbol inventory](../METHODS.md). Hand-curated; `(LNN)` markers are refreshed by `tools/refresh_methods_linenos.py`.

Layer 6 (Observability) is fully shipped — traces + metrics + structlog→OTLP log bridge, with W3C TraceContext propagation helpers for cross-process correlation (Python ↔ ROS 2 ↔ C++ safety kernel). Layer 4 (Reasoner) ships the live `ReasonerCore` direct-dispatch loop below; Layer 5 (C++ safety kernel) is still planned. This file also covers the WAM Protocol package (`python/wam/`) — an optional planning-layer component, not one of the seven core layers.

### `python/reasoner/src/openral_reasoner/palette.py`
_Closed-set `ToolPalette` + builder. Three tool variants (reload_gst_pipeline / lifecycle_transition / emit_prompt) are always available; `execute_skill` is gated by the installed-rSkill registry filtered by `RobotCapabilities` + license posture. Palette carries per-skill metadata (`RSkillToolEntry`), not just opaque ids — the LLM gets one tool per skill with description + action verbs + object/scene tags._

Mirrored from the matching `RSkillManifest` fields at palette-build time.
- `class ContinuousDetectorEntry(BaseModel)` (L110) — Frozen coverage record for a `mode: continuous` detector — surfaced to the LLM as *coverage* (not a tool) so it can read world state for tracked objects and reserve `locate_in_view` for the long tail. - `class OnDemandDetectorEntry(BaseModel)` (L217) — Frozen record for a `mode: on_demand` open-vocab locator surfaced as a selectable `locate_in_view` option (a prompt-able **read-only** tool, never an ExecuteRskill policy). Fields: `rskill_id: str`, `alias: str` (short selector the LLM passes as `LocateInViewTool.detector`), `description: str` (capability hint).
- `detector_alias(rskill_name) -> str` (L138) — Short LLM-/operator-facing detector id: strips the `OpenRAL/` org + `rskill-` kind prefixes (`"OpenRAL/rskill-omdet_turbo-any-locator-fp16"` → `"omdet_turbo-any-locator-fp16"`). Single source of truth for the alias the reasoner routes on.
- `detector_service_segment(alias) -> str` (L151) — ROS-safe service-namespace segment for an alias (hyphens → underscores), so the locate service lives at `/openral/perception/<segment>/locate_in_view`.
- `locate_in_view_service(detector, *, default="") -> str` (L200) — Resolves the `locate_in_view` service for a (possibly empty) selector: empty `detector` → `default`; empty resolved alias → the legacy `/openral/perception/locate_in_view` (single-detector back-compat); else the namespaced service. Shared by the reasoner dispatch and the deploy launch (which names each locator node's service).
- `resolve_locate_in_view_detector(detector, *, known_aliases) -> str` (L162) — Normalizes an LLM-supplied `detector` value to `""` when it names no configured on-demand locator, so an unrecognised alias (observed live: an uncurated model passed the literal word `"default"`) degrades to the deployment default via `locate_in_view_service` instead of resolving to a namespaced service that never existed. Pure, doctested; called by `reasoner_node._dispatch_locate_in_view` before resolving the service.
- `class ToolPalette(BaseModel)` (L279) — Frozen palette presented to the LLM each tick. Fields: `skills: tuple[RSkillToolEntry, ...] = ()` (primary surface), `execute_rskill_ids: frozenset[str] = frozenset()` (back-compat — auto-derived from `skills` via the `_derive_execute_rskill_ids` model-validator), `sensor_ids: frozenset[str] = frozenset()`, `node_ids: frozenset[str] = frozenset()`, `continuous_detectors: tuple[ContinuousDetectorEntry, ...] = ()` (`mode: continuous` detectors for the active robot; coverage, not tools), `spatial_memory_available: bool = False` (gates the two read-only `recall_object` / `resolve_place` query tools; off unless the reasoner_node has a SpatialMemory backend wired), `detector_available: bool = False` (gates `locate_in_view`), `on_demand_detectors: tuple[OnDemandDetectorEntry, ...] = ()` (selectable locator options for `locate_in_view`), `scene_query_available: bool = False` (gates `query_scene`; independent of `detector_available`), `memory_available: bool = False` (gates the self-maintained-memory tools `memory_write` (write) + `memory_search` (read-only archival recall); off unless the reasoner_node has a `MEMORY.md` wired via `memory_md_path`). Cross-validator `_check_skills_match_ids` rejects callers that pass both `skills` and `execute_rskill_ids` with disagreeing ids.
- `build_tool_palette(*, installed_skills, robot_capabilities, sensor_ids=(), node_ids=(), commercial_deployment=False, spatial_memory_available=False, detector_available=False, scene_query_available=False, task_progress_available=False, memory_available=False) -> ToolPalette` (L412) — A skill is included iff it is not an unresolved scaffold (`RSkillManifest.is_scaffold_placeholder` — drops `rskills/template/`, which the `rskills/*/rskill.yaml` glob otherwise admits as a `role: s1` skill a weak LLM can pick and the decode guard can't reject), role=s1, kind ∉ {detector, segmenter} (both are perception producers, not ExecuteRskill-dispatchable), capability flags satisfied, embodiment tags intersect, and (when commercial) license allows commercial use. A `mode: continuous` detector is instead collected into `continuous_detectors` (coverage for the LLM, never an ExecuteRskill tool); a `mode: on_demand` detector is collected into `on_demand_detectors` (selectable `locate_in_view` options via `detector_alias`, never an ExecuteRskill tool). A `kind: segmenter` skill is dropped outright and surfaced nowhere: the LLM never asks for a mask, so unlike an on-demand detector it is not even a selectable option — its only consumer is the HAL's vision attachment-evidence producer. Emits `RSkillToolEntry` records (manifest `description`/`actions`/`objects`/`scenes` mirrored in) in stable id-sorted order so the LLM tool schema is deterministic. `spatial_memory_available` forwards the read-only `recall_object`/`resolve_place` tools; `detector_available` forwards the read-only `locate_in_view` tool; `scene_query_available` forwards the read-only `query_scene` tool; `memory_available` forwards the `memory_write` + `memory_search` tools. All are `ToolPalette` fields gated in `tool_use` so the LLM only sees a tool when its dispatcher is wired; `detector_available` and `scene_query_available` are independent (localization vs scene-state reasoning). The reasoner_node dispatches `query_scene` via `_dispatch_query_scene` → `/openral/perception/query_scene` and re-prompts with the answer (frame_id `scene_vlm`).
- `task_space_disagreement(manifest, description, hal_mode, legacy_ok) -> str | None` (L52) — Phase 2 (warn-only). Pure (no ROS) shadow gate: builds `TaskSpace.from_action_contract(manifest.action_contract, description)` and runs `task_space_compatible(..., hal_mode)`, returning a warning string ONLY when the canonical gate disagrees with the caller's `legacy_ok` verdict, else `None` (and `None` for non-actuating skills with no `action_contract`). Called by the reasoner deploy-palette filter (alongside `_action_executable`) and `tools/rskill_publisher._validate_task_space` to surface cross-layer mismatches (slot EE-name / joint-width) without changing the drop/publish decision. Phase 4 makes `task_space_compatible` authoritative.

### `cpp/openral_safety_kernel/include/openral_safety_kernel/collision.hpp`
_Allocation-free attached-payload contact handling, plus the staged 26-DOP → exact-convex-hull narrow phase for the arm-link-vs-world-voxel check (design + measurements: [`collision-hull-narrow-phase.md`](../reference/collision-hull-narrow-phase.md), on top of [`collision-tight-geometry.md`](../reference/collision-tight-geometry.md) §12.2)._

- `struct CollisionHit` — one collision check's outcome and, on a hit, the E-stop evidence. `link_a` / `link_b` / `min_distance` always describe **one** geometry pair: the deepest pair that actually tripped the gate. `sweep_min_distance` is the separate sweep-wide minimum over every checked pair — including pairs that stayed clear of the margin and pairs the gate exempted (a live support-contact witness, or the payload's own uncleared occupancy residue) — and never supplies the evidence distance. With no hit, `min_distance == sweep_min_distance` (the clearance; `+inf` when nothing was compared). Every `check_*_collision` in this header returns it under that contract. `place_allowance_active` is disclosure on top of that, never a decision: it says the reported pair tripped a margin the ADR-0097 approach allowance had *reduced*, so an incident review can tell that stop apart from an ordinary one without changing the distance quoted for it. `advisory` (#176) is the one field that *is* a decision, and the narrowest one in the header: set only for an attached payload against world occupancy, inside its own live declared region, within `place_advisory_depth` of the allowance — the caller then refuses the candidate action without latching a fault or asserting E-stop. `hit` is still true (an advisory hit is a refusal, not a pass), it is never set for a robot link, and `fold_pair` ranks a hard trip above an advisory one at any depth so a shallow latching pair can never be masked by a deeper refusable one. `place_target_adjudicated` (ADR-0098) says the reported distance is to the declared place target's **own geometry**, not to the occupied cell `link_b` indexes — the caller then names the declared body rather than the cell, so the evidence can never quote one geometry's distance under another's identity.
- `hull_hull_distance(a, b, margin, fallback, depth_is_box_bound = nullptr) -> double` — stage 2 for a self-collision pair (#191): GJK on the two links' exact hulls, replacing the OBB SAT when both links ship stage-2 geometry. The optional out-parameter reports whether the returned number is the **box's bound** rather than a hull measurement: GJK proves an overlap but does not size it (that needs an expanding-polytope step this kernel does not run), so on the overlapping branch `fallback` stands. Sound — the hull is contained in its box, so the box can only report *more* penetration — but loose: −31.97 mm for a ~1.5 mm hull interpenetration on `panda_link5`↔`panda_link7`. Surfaces as `CollisionHit::depth_is_box_bound`, `safety.collision depth_is_box_bound=`, and the `safety.depth_is_box_bound` span attribute. Disclosure, never a gate — nothing branches on it, and the trip decision is unchanged.
- `check_contact_force_gate(attached) -> ContactForceGateResult` — ADR-0100 (survey Path C). The declaration-scoped contact-force gate: at the instant of a place the true clearance *is* zero, so no geometric margin separates "set the object down" from "crush it" (survey §9 point 4), and this reads the axis that does. **It only ever adds a refusal.** The caller evaluates it *after* every geometric check has already passed, so the only configurations it can reach are ones the kernel was about to accept — there is no branch by which it widens a margin, creates an exemption, or lets force license what geometry refused, and the return type has no way to express one. Arms only when all four hold, each failing toward the shipped geometry-only behaviour: `attached.force_gate.valid` (a live declaration with a positive in-range threshold; dispatch's default is `0.0`), the object's bit is in `force_gate.object_mask`, a witness is present and names the declared target, and `contact_force_calibrated`. Comparison is inclusive, so "up to N newtons" permits N; the **deepest** overrun is the one reported (single-pair coherence). `kMaxContactForceThresholdN = 140.0` mirrors `PlaceDeclaration.MAX_CONTACT_FORCE_THRESHOLD_N` — ISO/TS 15066 Table A.2's quasi-static hands/fingers limit — so a schema-valid declaration can never overflow the kernel. Allocation-free, `O(n_objects)` over a cap of eight.
- `place_approach_allowance_cap(resolution) -> double` — the place approach allowance's cap at a live voxel `resolution`: `min(1.5 × voxel, 4 cm)` (`kPlaceApproachAllowanceVoxels`, `kMaxPlaceApproachAllowanceM`), `0.0` for an unusable resolution. `constexpr`, header-inline. One definition, so the geometry and the `safety.place_region_armed` log line cannot quote different numbers for the same map.
- `place_approach_allowance(grid, object_index, center) -> double` — ADR-0097's 2026-08-14 amendment. Margin reduction the live place declaration grants this payload against this occupied cell, or `0.0`. Returns the reduction only when the region is valid, the object is in its `object_mask` (and under the eight-object schema cap), the box is finite and non-degenerate, and the cell **centre** is inside it (exact point-in-OBB in the box's own frame — an oriented box, because the axis-aligned hull of a rotated receptacle is strictly more permissive). The reduction is `place_approach_allowance_cap(grid.resolution)`, evaluated against the *live* resolution so a map that coarsens mid-run can only shrink it. `kMaxPlaceApproachAllowanceM = 0.04` and `kPlaceApproachAllowanceVoxels = 1.5` are maintainer-set binding conditions (HZ-0097-4 mitigation 1 as calibrated 2026-08-15 by ADR-0097's Second Amendment; HZ-0095-2 is the precedent), not implementation choices — 37.5 mm at sim's 25 mm grid, 40 mm (not 75) at a real 50 mm one. Reduces the margin only — it is not an exemption, so deepening past it still stops, the reported distance stays the pair's true distance, and arm-vs-world is untouched.
- `enum class PlaceRegionStatus` — Outcome of a place-region ingest: `kOk`, `kNoObject`, `kBadPose`, `kBadExtents`, `kDegenerate`, `kOversize`, `kOversizeVolume`, and (ADR-0098) `kBadGeometry` / `kGeometryOverflow` for the declared target's own primitives. Identical to the geometry (every non-`kOk` value means *no allowance*), and not at all identical to the reader: `kNoObject` is the ordinary pre-grasp state — dispatch declares the place phase before the payload is attached — while the rest are producer errors. The single `reason=bounds` label the node used for all of them is what round-8 reported as 672–811 warnings per run, none of them about a bound.
- `ingest_place_region(pose, half_extents, object_mask, out) -> PlaceRegionStatus` — Validate a producer-supplied region into `out`, fail-closed toward *no allowance* rather than a dropped message (a bad region can only make the kernel more permissive, so refusing it restores the pre-amendment margin — the opposite direction from a malformed support attestation). Rejects a non-finite pose or half-extent, a non-positive or >`kMaxPlaceRegionHalfExtentM` (1.5 m) side, a box above `kMaxPlaceRegionVolumeM3` (8 m³ — a declaration names one receptacle, not a room), and an empty `object_mask`, each under its own status. `kOk` iff `out.valid` was set; every other value leaves `out` inert. Not on the hot path.
- `ingest_place_target_geometry(geometry, store, region) -> PlaceRegionStatus` — ADR-0098 (collision-safety survey Path B). Lower the declared target's **own** collision primitives into an already-validated `region`, so a payload can be adjudicated against the modelled receptacle instead of against the 25 mm cubes it was quantised into. Split from `ingest_place_region` because the two answer different questions — the box says *where* the receptacle is, this says *what it is*. Call it only after the box validated; on anything but `kOk` the caller resets the whole region, because a producer that cannot describe the target it declared is not one whose box is trusted either (#142/#146), and the fail-closed direction is no allowance at all rather than a silent downgrade to box-only. `store` must already be sized to `kMaxPlaceTargetPrimitives` (64, matching `openral_core.PlaceRegion.MAX_GEOMETRY_PRIMITIVES` — one bound declared on both sides of the wire) and has to outlive every check that reads the region, since `PlaceApproachRegion::geometry` is a view into it. Empty geometry is the ordinary case and leaves the region exactly as `ingest_place_region` left it. Rejects a malformed shape (`kBadGeometry`) and a list past the cap (`kGeometryOverflow`) — half a receptacle is a worse model than none, because the missing half would be adjudicated as if it were not there. Not on the hot path.
- `place_target_distance(region, prim, prim_xf) -> double` — ADR-0098. Exact surface distance from one attached payload primitive (base frame `prim_xf`) to the declared target's own geometry, `+infinity` when the declaration ships none — which is what makes "no geometry" collapse to the pre-ADR-0098 path at every call site without a branch. The mm-resolution half of Path B: the voxel grid can only answer "is this 25 mm cube occupied", this answers "how far is the payload from the receptacle it was dispatched to place into", through the same certified primitive routines every other check in the header uses — no coal, no EPA, no hot-path allocation (survey §4.1). Allocation-free.
- `place_region_status_reason(status) -> const char*` — Stable snake_case token for a `PlaceRegionStatus` (`no_object`, `bad_pose`, `bad_extents`, `degenerate`, `oversize`, `oversize_volume`, `bad_geometry`, `geometry_overflow`, `ok`), used as the `reason=` key of the node's place-region log lines. Never null; one token per outcome.
- `support_contact_exempts(object, object_xf, center, resolution, slack) -> bool` — ADR-0092 D6. Does object `i`'s attested support contact explain this occupied cell? Index-free and quantisation-exact: lifts the attested plane out of the object frame each call (so it survives a driving base re-phasing the lattice), then requires the cell to be inside the attested patch laterally and no higher above the plane than `half_resolution·(|n.x|+|n.y|+|n.z|) + attested depth + slack + resolution` — the voxel cube's own projected half-width, not a widened tolerance, plus one voxel of **co-planar headroom** (hazard log Entry 012, "Calibration 2026-08-15": adjacent co-planar structure sits about one voxel above the attested plane while support contact persists; round-8 r2 measured +42.9 mm against a ~15-19 mm envelope). That fourth term widens **height only, inside the unchanged lateral patch**, and is mirrored by `support_patch_withholds` ([03-world-state.md](03-world-state.md)) in lockstep. The caller must have established the witness is live; this does not read `grid.support_witness_live`.
- `update_support_contact_witnesses(attached, scratch, grid, live_mask, margin) -> uint8` — Refresh the per-object witness latch against the measured configuration. A bit survives only while some cell the witness would exempt is still within `margin` of the payload; on separation it clears and this never sets it again, so re-contact after a lift and a regrasp are both new violations. Re-arming is the lifecycle node's job, keyed on the attestation's identity. Returns 0 when the map is unusable (fail-closed). **The evidence it consults is occupancy**, so it is partitioned against the Layer-2 payload clearing: `openral_octomap_bridge`'s `clear_attached_payload_cells` withholds the cells inside the attested patch (`support_patch_withholds`, [03-world-state.md](03-world-state.md)) precisely so this latch keeps a cell to measure. A clearing that takes the support surface too makes this declare separation while the payload has not moved.
- `update_attached_voxel_contacts(attached, scratch, grid, contact_mask, contact_distance, mask_capacity, distance_capacity, snapshot) -> bool` — Snapshot the occupied voxel contacts present at attachment and refresh them against the measured payload pose; bits are never added after the snapshot. Only the *embedded* subset still exempts anything (the payload's own uncleared occupancy residue, at least half a voxel inside it at snapshot time). The non-deepening index-keyed allowance was removed — voxel indices decorrelate as the base drives while the physical contact persists — and `update_support_contact_witnesses` replaced it.
- `place_advisory_depth(resolution) -> double` — `min(0.2 × resolution, 5 mm)`, the depth past the place approach allowance within which an attached payload's world contact is *refusable* rather than latching (#176). Sized from the measured 0.72 mm overshoot of the 2026-08-26 baguette place (−38.22 mm read at a −1.4 mm physical contact), not from a voxel multiple: per-cell penetration saturates near the allowance itself, so a wider band would cover the whole reachable range and bound nothing. `0.0` for an unusable resolution, which collapses the band to today's latched stop.
- `check_voxel_collision(model, scratch, grid, margin) -> CollisionHit` — Every robot primitive (FK'd via `scratch`) against the occupied cells of a dense voxel `grid`, bounded to the cells inside each primitive's inflated AABB, each occupied cell treated conservatively as a cube at the cell centre. Never sets `CollisionHit::advisory` — a robot link against the world is a latching stop at any depth. The grid is an **oriented** lattice (`VoxelGrid::pose`, since 2026-08-25): its axes are the source map's, so each link is carried into the grid's axes once — one `compose` per link, off the per-cell loop — and the cells stay axis-aligned cubes there. That is required, not merely tidy: `dop_cell_lower_bound` measures a cell against three world-axis slabs using `half_side` directly, which is a cube only in the frame `tight_pose_init` was given. Distances are rigid-motion invariant, so an identity `pose.r` reproduces the pre-oriented answers (measured: 2.8e-17 m drift, no verdict or evidence-cell change over 200 random cases). A boxed link whose `CollisionModel::box_hull` entry names a `LinkHull` runs the **staged** narrow phase instead of `box_box_distance`: `dop_cell_lower_bound` on every occupied cell, then `hull_cell_distance` only for the cells the DOP cannot clear (capped at `kMaxStage2PerCheck` per call). Both stages are strict subsets of the shipped OBB — proved at configure time by `validate_tight_geometry` — so the broad-phase window is unchanged and cannot miss a cell it visits today; the reported distance is still a lower bound on the true link-mesh-to-cell distance, merely a **tighter** one, which is the whole point (the kernel gives away less clearance it never had). Links without tight geometry, every capsule-lowered robot, and every other check in this header keep the shipped primitive path exactly as it is. Allocation-free.
- `kDopAxes` / `kDopAxis[kDopAxes][3]` — The 26-DOP's 13 unit axis directions (3 face, 4 corner, 6 edge; each carrying a `lo`/`hi` slab, hence 26 halfspaces), in the owning OBB's own local frame. The first three **are** the box's axes, which is what makes "the DOP is inside the shipped box" a two-line configure-time check rather than a polytope enumeration. Deliberately mirrored in Python as `openral_core.schemas.DOP_AXES` — [14-duplication-watch.md](14-duplication-watch.md) item 12.
- `kMaxTightHullVertices = 320` — Hard ceiling on a stage-2 hull's vertex count, enforced at configure time. A **cost** bound set by measurement, not a geometry choice: the stage-2 support function is an exhaustive scan of the vertex list (the only form whose result is provably the true support, which is what makes `hull_cell_distance`'s bound sound), so its cost is linear in the count and the staged path stops being cheaper than the `box_box_distance` it replaces past roughly 320. The Panda's `link1` hull has 1588 vertices and measured 0.76x the shipped routine at 400 occupied cells, so it is refused stage 2 and runs stage 1 only — still a strict tightening (25.7 mm of support excess against the shipped box's 53.3 mm). Mirrored as `MAX_TIGHT_HULL_VERTICES`.
- `kTightContainmentEpsilonM = 1e-9` — Floating-point slack `validate_tight_geometry` allows when checking a stage-2 vertex against its own DOP slabs. The two are tangent *by construction* (the slab bound is the maximum of `u·x` over the same vertex set), so the true relation is equality on at least one vertex per axis and the offline producer and the kernel merely evaluate that dot product in different orders. The DOP-inside-the-OBB check takes no slack at all. Mirrored as `TIGHT_CONTAINMENT_EPSILON_M`.
- `kGjkMaxIterations = 24` / `kGjkTolerance = 1e-9` — Iteration ceiling and convergence tolerance for the stage-2 GJK loop. Hitting the ceiling is not a failure mode: every iteration's result is a *lower* bound on the true distance, so a truncated run is simply more conservative than a converged one.
- `kMaxStage2PerCheck = 32` — Ceiling on stage-2 invocations in ONE `check_voxel_collision` call, across every link; past it the check keeps refining with stage 1 and the shipped `box_box_distance`, so the cap can only make the answer more conservative. It exists because stage 2's cost is driven by how many cells stage 1 *cannot* clear — a property of the map, not the robot: two cells reach stage 2 at the measured RoboCasa start state, but clutter pressed against the arm at the real HAL's 20 mm world-voxel margin drove that toward every occupied cell and turned a 1.07x speedup into a 1.5x slowdown unbounded. **Changing it changes a real-time bound: it belongs in the hazard log.**
- `struct LinkHull` — Tight convex geometry refining ONE `Obb` in `CollisionModel::boxes`, all in that box's own local frame so the broad-phase window never moves. Fields: `dop_lo[kDopAxes]` / `dop_hi[kDopAxes]` (stage 1, always on — tangent halfspaces, so mesh containment is true by construction) and `vertex_first` / `vertex_count` (stage 2, CSR offset into `CollisionModel::hull_vertices`; `vertex_count == 0` means stage 1 only, the representation `link1` uses).
- `CollisionModel::box_hull` / `hulls` / `hull_vertices` — The three new `CollisionModel` members carrying tight geometry. `box_hull` is parallel to `boxes`: the index into `hulls` for the tight representation refining that box, or `-1` for none. An **empty** `box_hull` means no box carries tight geometry — the pre-#166 behaviour every capsule-lowered robot and every manifest without `tight_geometry` keeps, and the gate that switches the staged path on. `hull_vertices` is the CSR-packed stage-2 vertex pool, box-local.
- `AttachedPrimitive::hull_index` / `AttachedModel::hulls` / `AttachedModel::hull_vertices` — The payload twin of `CollisionModel::box_hull` / `hulls` / `hull_vertices` (#266), and the same representation: `hull_index` is the entry in `hulls` refining that primitive's box in the **payload-vs-world-voxel check only**, `-1` for none. Unlike a robot's — fixed, shipped, validated once at configure time — a payload's hull arrives on every world-state message from a live producer, so both buffers are sized to the primitive cap at configure time (16 x 320 x 24 B ≈ 123 kB) and refilled in place by `ingest_attached_objects`; the hot path still never allocates. Ingest **fails DOWN**, not closed: a refinement that cannot be proved contained (`validate_tight_hull`) is dropped and the primitive is checked as the plain box — refusing the whole attachment would drop the payload's geometry, which is the unsafe direction. An over-budget hull is refused whole, never truncated to the first `kMaxTightHullVertices`, since a truncated hull no longer contains its mesh. Exists because `extract_body_primitives` lowers a carried mesh geom to its local AABB, whose corners stood a median 50.78 mm (max 88.22 mm) proud of the mesh across the 2026-09-10 resolution A/B while 97 % of the 15 mm arm's stops were payload-vs-world. `check_attached_voxel_collision` runs the staged path under its own `kMaxStage2PerCheck` budget; ADR-0098's place-target adjudication keeps reading the **shipped box** distance, so the refinement removes stops outside that branch and changes nothing inside it.
- `enum class TightGeometryStatus` — Why `validate_tight_geometry` refused a model: `kOk`, `kBadArity` (the three arrays' sizes disagree), `kEscapesBox` (a DOP slab reaches outside the shipped half-extents), `kHullEscapesDop` (a stage-2 vertex sits outside its own DOP), `kTooManyVertices`, `kDegenerate` (non-finite or inverted slab). Anything but `kOk` is fail-closed at the call site: the kernel keeps the shipped OBB narrow phase for **every** link rather than load geometry it could not prove contained.
- `validate_tight_hull(hull, half_extents, vertices) -> TightGeometryStatus` — The containment proof for **one** tight representation against **one** box: slabs finite and not inverted, `hull ⊆ 26-DOP ⊆ box`, vertex count within `kMaxTightHullVertices`, the CSR slice in range. Shared by the robot's configure-time `validate_tight_geometry` and the payload's per-message `ingest_attached_objects` (#266), so a link hull and a carried-payload hull are never held to two different standards. Allocation-free.
- `validate_tight_geometry(model, offending_box) -> TightGeometryStatus` — Prove, at configure time, that every declared tight representation is a subset of the shipped OBB it refines — the single assertion that keeps `check_voxel_collision`'s broad-phase reach correct without changing a line of it. Checks the chain `hull vertices ⊆ 26-DOP ⊆ shipped OBB`, both links definitional rather than fitted (a stage-2 vertex must satisfy all 26 slab constraints; the DOP's first three axes are the box's own, so three bounds prove the whole polytope). The remaining obligation — that the true link *mesh* is inside the DOP — is discharged offline by construction and re-proved by `tests/unit/test_collision_tight_geometry.py`; the kernel never sees a mesh. `offending_box` receives the offending index on refusal. Not on the hot path; allocation-free.
- `tight_geometry_status_reason(status) -> const char*` — Stable snake_case token naming a `TightGeometryStatus`, for the `reason=` key of the kernel's tight-geometry log line. Never null; unknown values read `unknown`. Same contract as `place_region_status_reason`.
- `struct TightPose` / `tight_pose_init(hull, hull_vertices, box_xf, half_side, out) -> void` — Per-link-pose constants for the staged narrow phase, hoisted once per checked configuration outside the cell loop (the kernel streams cell centres against a fixed link pose, so every term depending only on the pose is computed once): each DOP axis in the base frame, its dot with the box origin, the voxel cube's support radius on it, the slab bounds, the base-frame AABB of the DOP's own axis-slab box, and the stage-2 vertex pointer. Holds pointers into the caller's `CollisionModel` — it owns nothing and must not outlive it. Allocation-free.
- `dop_cell_lower_bound(pose, center, half_side, best_axis) -> double` — **Stage 1**: a conservative lower bound on the surface distance between the link's 26-DOP and the occupied voxel cube centred at `center`. Separating-axis over 16 directions — the DOP's own 13 (where its support is exact, being a tangent slab) plus the three world axes (where the axis-slab AABB over-estimates its reach, which only makes the bound more conservative). The maximum gap over any set of unit axes lower-bounds the true Euclidean distance, the same argument `box_box_distance` already rests on, applied to a tighter provably-contained solid. `best_axis` (nullable) receives the winning separating axis's base-frame normal — stage 2's search direction, and why stage 2 converges in one or two iterations instead of five. Allocation-free.
- `struct GjkWitness` — Stage-2 warm-start carried between adjacent cells in one window and between consecutive steps of the predictive horizon. Stores hull vertex **indices** and cube-corner sign codes, never Minkowski-difference points: the cube moves from cell to cell, so cached points would not lie in the current difference set and GJK's bounds would stop holding. Indices stay meaningful because they are only hints, re-evaluated against whichever cell is being checked; `n == 0` is a cold start.
- `hull_cell_distance(pose, center, half_side, seed_dir, margin, fallback, witness) -> double` — **Stage 2**: a lower bound on the surface distance between the link's exact convex hull and the occupied voxel cube, equal to it (to `kGjkTolerance`) on convergence. GJK over the hull's vertex list against the cube's eight corners, seeded with stage 1's winning separating-axis normal. **Conservatism does not depend on convergence** — every returnable value is a supporting-hyperplane lower bound, so the iteration cap, the early exit once the bound clears `margin`, and the overlap case can each only make the answer more conservative; on overlap, and whenever the bound would be worse than stage 1's, `fallback` (stage 1's figure, which is ≤ 0 whenever hull and cell actually overlap, because the DOP contains the hull) is returned instead. The support function is a deliberate exhaustive scan, which is why `kMaxTightHullVertices` exists: a hill-climbing support over an edge graph can stop one vertex short under floating point, and a support that is not the true maximum turns the bound into an **over**-report of clearance. Allocation-free (fixed-size stack simplex).
- `hull_hull_distance(a, b, margin, fallback) -> double` — **Stage 2 for a self-collision pair** (#191): the same GJK as `hull_cell_distance` with the voxel cube's eight corners replaced by a second hull's vertex list. `check_self_collision` calls it for a box↔box pair whose OBBs come within `margin` when **both** links ship a stage-2 hull; the OBB stays the broad phase and the `fallback`, so a pair the boxes clear costs nothing and a manifest without `tight_geometry` is bit-for-bit unchanged. It exists because the OBB cannot answer for interleaving links: on `panda_link5`↔`panda_link7` the boxes overlap on 86.38 % of the pair's `(joint6, joint7)` grid while the real geometry interpenetrates on 6.60 %, and **no margin separates the populations** (deepest real collision at a box gap of −8.37 mm, shallowest false one at −36.64 mm) — which is why that pair shipped ACM-exempted "under protest" from #169 until this landed. Refining is the *less* conservative direction and that is the point: the hull is `conv(collision mesh)`, so it contains what the robot is made of and cannot clear a pose the real links occupy. Unlike the cell routine it does **not** stop at the first bound clearing `margin` — its result is the reported `sweep_min_distance`, and the early exit was measured returning 4.2 mm for a pair genuinely 60.0 mm apart. Cold-started (a self-pair is checked once per configuration, so there is no neighbouring cell to warm-start from). Measured cost on the shipped `panda_mobile`: `check_self_collision` 0.758 → 2.303 µs/call, +24.7 µs over a 16-step horizon, 0.25 % of a 10 ms budget. Allocation-free.

### `packages/openral_safety/openral_safety/urdf_lowering.py`
_Offline URDF(+SRDF) → manifest collision-model lowering tool; lazy-imports `yourdfpy` / `trimesh` (the `[lowering]` group). Populates `robot.yaml`'s `collision_geometry` + `allowed_collision_pairs` (the hand-reviewable manifest path), distinct from `mjcf_lowering` (the runtime MJCF path)._

_An ACM entry **removes** a self-collision check, so every rule here fails toward **fewer** entries: a withheld entry costs a false E-stop, an unearned one hides a real collision. The always-colliding verdict is decided by `_certified_always_colliding` — private, but the module's core safety argument. It is branch-and-bound over the pair's relative-DoF subspace (the joints between the two links; at most 4 fleet-wide) with a Lipschitz bound: turning joint j by δ moves a point at radius R by ≤ R·δ, so over a cell every point of the far link moves ≤ `ε = Σ R_j·w_j/2` and `gap(q) ≤ gap(centre) + ε`. A cell certifies when `gap(centre) + ε <= margin`; a cell with `gap(centre) > margin` is a **witness** that the pair separates and rejects the pair outright; otherwise it splits on the axis contributing most to ε. The budgets `_CERTIFY_MAX_DOF=5` / `_CERTIFY_MAX_CELLS=400_000` / `_CERTIFY_MAX_LEVELS=96` / `_COARSE_NODES=7` are **cost knobs, not soundness knobs** — hitting any of them withholds the entry, which is pinned by test. Since #191 it also withholds outright for a pair whose links **both** declare `tight_geometry`: the kernel decides those on the exact hulls (`hull_hull_distance`) and `hull_gap >= box_gap` everywhere, so "the boxes always overlap" — all `shape_distance` can show — no longer implies the kernel trips. No shipped robot loses an entry to this; every `panda_mobile` row is adjacent or SRDF-sourced._

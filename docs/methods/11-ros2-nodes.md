# ROS 2 Lifecycle Nodes (`packages/`)

> Part of the OpenRAL [public-symbol inventory](../METHODS.md). Hand-curated; `(LNN)` markers are refreshed by `tools/refresh_methods_linenos.py`.

Thin wrappers around the Python-layer adapters; each exposes a single
`main()` entry point for `ros2 run`.

### `packages/openral_hal_node/openral_hal_node/lifecycle_node.py`

- `main() -> None` (L28) — The one manifest-driven HAL lifecycle node every robot runs: `openral_hal.lifecycle.make_lifecycle_main_from_manifest(node_name="openral_hal_node")`, i.e. a `ManifestHALLifecycleNode` that builds its HAL from the `robot_yaml` + `hal_mode` parameters via `openral_hal.build_hal`. Heartbeat, `/openral/safe_action` consumer and `/openral/estop` latch come from `HALLifecycleNodeBase`. `openral deploy sim|run` launches it under the ROS node NAME `openral_hal_<robot_id>` (a `__node:=` remap — not a package name). Covered by `packages/openral_hal_node/test/` (parametrised by robot manifest) and `tests/integration/test_openarm_hal_lifecycle.py`.

### `packages/world_state/openral_world_state_ros/lifecycle_node.py`

- `main() -> None` (L74) — `WorldStateAggregator` lifecycle node. Subscribes joint/policy/camera (`camera_topic(name)` per `camera_names` entry; the `camera_topic_prefix` parameter was removed by ADR-0108; `object_depth_points_topic` defaults to `""` = no depth fallback)/attachment streams and publishes typed fast/slow world-state summaries; attachment updates atomically replace the prior set so multiple changes never expose a partial model; the envelope's `place_declaration` and `grasp_declaration` are relayed `AttachmentState -> WorldStateStamped` (`_place_declaration_from_idl` / `_grasp_declaration_from_idl`, `_fill_place_declaration` / `_fill_grasp_declaration`; a grasp declaration's `target_queries` are encoded with the `ObjectQuery` message factory). Issue #418: subscribes `tracked_objects_topic` (default `/openral/tracked_objects`, RELIABLE/VOLATILE/KEEP_LAST 1) and relays the object tracker's set as `WorldStateStamped.tracked_objects` (`_fill_tracked_objects` / `_tracked_objects_from_idl`), `tracked_objects_valid` false when absent or stale. Shared with `rskill_runner_node`.
  - `_direct_image_frame_sensors() -> set[str]` — The `direct_image_frame_sensors` parameter as a set; `_on_image` skips these cameras entirely, since the co-located sensor leg's pump already writes them to the aggregator at full cadence.
  - `_on_attachment_state(msg) -> None` — Validates and applies one complete attachment snapshot to the aggregator, then publishes a world-state message on the fast topic at once (`_publish_snapshot(event=True)`): the kernel reads attachments only from that message, the timer runs on the node clock, and a sim twin's attachment perception barrier holds that clock still while it waits for the kernel's ack of exactly this revision (a revision arriving during the hold used to wait ~2 s for the clock to move).
  - `_publish_snapshot(*, event=False) -> None` — Timer callback: snapshot to `WorldStateStamped` on the fast topic (and every Nth tick the slow one); `event=True` is the extra publish outside the timer, which is not a tick and leaves the slow cadence alone.
- `_IDL_DIAG_TO_STR: dict[int, str]` (L993) — `DiagnosticState.diag_status` uint8 → the lowercase label (`"ok"`/`"warn"`/`"stale"`/`"error"`) `world_state_from_idl` writes onto `openral_core.WorldState`.
- `world_state_from_idl(msg) -> WorldState` (L1001) — Symmetric inverse of `build_world_state_stamped_msg`: reconstructs an `openral_core.WorldState` from a `WorldStateStamped` msg. Used by the reasoner node to feed real state into its `ContextRenderer`; `image_frames` is always `None` (the IDL carries image topic refs, not inline pixels). Each detected object's `bbox_3d` comes from the `detected_object_bbox_valid` / `_bbox_min` / `_bbox_max` arrays (ignored unless index-aligned with the labels, so an older publisher decodes as no boxes); the reasoner seeds named grasp targets from it.
- `build_world_state_stamped_msg(node, world_state) -> WorldStateStamped` (L1194) — Inverse translation: a Pydantic `WorldState` → `WorldStateStamped` IDL msg. Parallel arrays are deterministically ordered (sorted by key) so two consumers comparing snapshots at the same timestamp see the same byte layout.

### `packages/world_state/openral_world_state_ros/object_tracker_node.py`
_Issue #418 WP D1. The object-tracker lifecycle node (`ros2 run openral_world_state object_tracker_node`); all decisions in `openral_world_state.object_tracker.TrackerSession`, the node owns the wire (README "Object tracker"). Its heartbeat also publishes `std_msgs/Bool` `/openral/object_tracker/hands_clear` (`TrackerSession.hands_clear_of_targets`)._

- const `DEFAULT_SEGMENT_SERVICE = "/openral/perception/segment_in_view"` (L94) — The `SegmentInView` server (the HAL vision bridge's own); kept local because Layer 2 does not import the HAL. Fixed (no longer a param, like `_MASK_TF_WAIT_S` 0.3 s, `_PROCESS_HZ` 15, `_HEARTBEAT_HZ` 2, `_ATTACHMENT_EVIDENCE_TIMEOUT_S` 1.0 s).
- `image_array(msg) -> NDArray` (L118) — `sensor_msgs/Image` → `(H, W)`: `32FC1` / `16UC1` → float64 metres, `mono8` → uint8; honours `step`; `ROSConfigError` on another encoding. Duplicates `openral_hal.depth_cloud.depth_grid_from_image` for depth (Layer 2 must not import Layer 0; see 14-duplication-watch).
- `intrinsics_from_info(msg) -> IntrinsicsPinhole` (L150) — The driver's live `K`.
- `pick_depth_frame(received_s, ready, now_s, wait_s) -> int | None` (L306) — Which waiting depth frame the tracker feeds: the newest one whose robot mask and tf are in (older ones dropped), else the oldest for ageing only once it waited `wait_s`, else keep waiting; a mask trailing by more than a depth period still pairs (issue #418, Spark restock 2026-10-24).
- `pick_masks(masks, box_xyxy, within_xyxy=None, *, inside_fraction=0.9) -> list[NDArray]` (L176) — The qualifying nested candidates, best first: with a box prompt (detector or a track's projected box) those ≥ 90 % inside it, the one whose rectangle matches the box best (IoU) first (SAM's nested candidates are a subpart, the object, and the object spilled onto its support); without one, those inside `within_xyxy` (a map seed's rectangle) or all, largest first. The node sends the rest as `TrackerResult.alternatives`.
- `backproject_pixel(depth_m, k, uv, *, win=2) -> tuple | None` (L220) — Optical-frame point under a pixel (median valid depth in a window); the `SegmentInView` prompt point.
- `detector_scores(metadata_json) -> tuple[float, ...]` (L240) — `LocateInView`'s detection scores, parallel to `detector_boxes` (#418: the tracker logs a low-score prompt that confirms).
- `detector_boxes(metadata_json, k) -> tuple[...]` (L260) — `LocateInView`'s `ObjectsMetadata` boxes rescaled to the depth raster.
- `main() -> None` (L454) — Entry point.
- `make_object_tracker_node() -> LifecycleNode` (L477) — `openral_object_tracker`: per-camera depth/`CameraInfo`/`robot_mask` subscriptions, `/openral/world_voxels`, `/joint_states` (manifest names, `sim_joint_name` aliases), `/openral/grasp_events`, the declarations; a frame waits `_MASK_TF_WAIT_S` (wall) for its exact-stamp mask and tf, else is fed for ageing only; one `SegmentInView` / `LocateInView` request in flight, answered with the frame it was issued on. A locate service/transport failure or nonempty `LocateInView.failure_reason` becomes a `TrackerResult.failure_reason` and query refusal cause; only a completed empty result is `locate_found_nothing`. Publishes `/openral/tracked_objects` on change + `_HEARTBEAT_HZ`, and `/openral/attachment_state` (bindings + declarations with the tracker-measured workspace and place regions and, in `tracking` only, the grasp region `TrackerSession.grasp_region`; heartbeated while joint states are fresh). Revisions seeded from wall time at activate (monotone across restarts). Addendum G escalations (`search_start_s` / `search_max_s` params, source s, defaults `TrackerParams`): each `unresolved` / `exhausted` `QueryEscalation` becomes an `ObjectQueryEvidence` (`escalation_evidence`; attempts = `SegmentInView`/`LocateInView` requests issued for that query) recorded as a structlog `object_tracker.query_escalation` (WARN / ERROR), a `world_state.object_query` span parented on the declaration's `trace_id` with the `ROSObjectNotInMemory` recorded, and a `FailureTrigger` (`KIND_OBJECT_QUERY`, WARN / FAIL, the declaration's `rskill_id` / `trace_id`) on `/openral/failure/world_state` for the reasoner. Param `wrist_links` (default 1; the launch passes `DeployRuntime.workspace_contact_wrist_links`) sizes the hand boxes as the kernel's hand links. `configure` fails with `hal_mode != sim` (both modes are sim-only), a missing `grounding_wait_s`, or a gripper the binder cannot model. One service call is in flight at a time; a call the scheduler abandoned past `segment_budget_wall_s` is removed from its client (`remove_pending_request`, `_drop_abandoned`) at the next issue and at cleanup, freeing its `CameraFrame` and never feeding a late reply.
- `escalation_evidence(escalation, query, attempts) -> ObjectQueryEvidence` (L336) — Issue #418: one `QueryEscalation` with its `StandingQuery` as typed failure evidence, including its owning action `invocation_id`; `waited_s` = source seconds since the query's current search started.

### `packages/openral_rskill_ros/scripts/runtime_node`

_Composed-runtime entry point installed as `lib/openral_rskill_ros/runtime_node`._ Reads the `robot_yaml` parameter, calls `compose_runtime`, and spins both lifecycle nodes on a `MultiThreadedExecutor`; for a real deploy it also opens every deploy-bound sensor reader before spinning. The script eagerly initializes GStreamer before any numpy/pydantic/rclpy import, since a later `rclpy.Node()` can segfault otherwise. Spins the world-state node on the C++ `EventsExecutor` (`start_world_state_executor`; falls back to sharing the multi-threaded executor with a stderr notice) and the skill runner on a 4-thread executor. Launch param `joint_states_topic` (resolved by `deploy_e2e.launch.py` via `openral_hal.hal_joint_states_topic`: scene override, else a real ros2_control HAL's `/<hal_node>/joint_states`) reaches **both** composed nodes through the launch's wildcard params: world_state's ingest and the runner's `ROSPublishingHAL` joint-state cache (`RskillRunnerNode` param `joint_states_topic`, `""` = `/joint_states`) share the one topic, so a ros2_control arm's 750 Hz broadcaster stream never wakes the Python executors. With a `deploy_config`, it loads the scene BEFORE `compose_runtime` and passes its `sensors:` as `deploy_sensors`; the sensor leg then reads readers off that merged description.

- `_prewarm_vla_imports() -> None` — Imports `torch` + `lerobot.policies.factory` early so the shared bulk of any VLA adapter's import cost is paid before any camera-reader thread exists. Must run ahead of `open_deploy_sensor_readers`, since a `transformers` import can otherwise starve a reader thread of the GIL for minutes.

_Completion check (2026-10-22): on the reward monitor's success stream (`CriticScore` whose `critic_id` ends `#success`) at/above 0.6, a `DETACH` on `/openral/grasp_events` or a track newly `released` on `/openral/tracked_objects` (`CompletionTrigger`, one check per 10 s, only while `/openral/reward/active_task` names a task and never while `/openral/attachment_state` holds a payload — a release fires once the hand is empty), it holds the runner (`/openral/rskill/hold`), asks `/openral/perception/query_scene` the reasoner's `COMPLETION_QUESTION` plus the release rule (a placement is finished only once let go) once per camera, and ends the goal (`/openral/rskill/complete`) only when every answer `parse_yes_no`s true; otherwise it releases the hold.

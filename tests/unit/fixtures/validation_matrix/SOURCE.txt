FILES, and how each was produced
--------------------------------

`<round>/<scene>/run_deploy_excerpt.log`
    Verbatim line subset of the round's `seed1_deploy.log` (1.7 MB), selected
    with, and only with:

        grep -E "safety\.|sim\.task_success_final|sim\.estop_ground_truth|\
sim\.estop_initial_configuration|place_allowance_active=1" seed1_deploy.log

    Every retained line is byte-for-byte the original, ROS launch prefix and
    all. The full logs are not in the repo because they are ~1.7 MB each.

`<round>/<scene>/run_monitor.jsonl`
    Verbatim line subset of the round's `seed1_monitor.jsonl`, produced by
    `attach_monitor4.py` (now `tools/_validation_matrix_monitor.py`). Kept:
    `monitor_started`, the FIRST `world_voxels` record (it carries the grid
    resolution the quantization budget is computed from), every
    `place_declaration`, every `world_state_attached`, each
    `attachment_state` at which the attached-object set changed plus the first
    one carrying a support witness, `failure_safety`, `estop` and
    `monitor_stopped`. The dropped records are the ~1200 `attachment_applied`
    acks and the periodic `world_voxels`/`snapshot` lines, which no verdict
    field reads.

`<round>/<scene>/run_goal.log`
    The dispatcher's single JSON line, complete and unmodified, from
    `run_xr1_full.py` (now `tools/_validation_matrix_dispatch.py`).

`<round>/metadata.json`
    THE ONE HAND-WRITTEN FILE. These rounds predate the harness, so they never
    wrote the metadata block `tools/validation_matrix.py` now emits; this
    restates what the round's own `NOTES.md`, runner script and artifacts say,
    in the harness's format. Field origins:

      executed_sha        — `git rev-parse 2edcf67`, the tip both NOTES.md
                            files name.
      started_at          — the ROS timestamp on the round's first
                            `safety.*` log line, converted to UTC.
      host / gpu_name     — `hostname` and `nvidia-smi --query-gpu=name` on the
                            validation host.
      launcher_path,
      repo_root           — the absolute launcher and `OPENRAL_REPO_ROOT` the
                            round's `run_matrix.sh` exported.
      stack_argv          — the stack the round pinned. The round expressed it
                            through a per-round scene copy's `runtime:` block;
                            the harness pins the same stack through the deploy
                            CLI's flags, which is what is written here.
      sync_groups         — the group set the round's NOTES.md records
                            (`--group robocasa --group sidecar-wire`).
      seed, rskill_id,
      scene_configs       — from the round's runner invocation.

    `overlay_built_at_ns` is deliberately ABSENT: these rounds did not record
    it, and the field is optional. Do not fill it in with a guess.
